# New Deviation — 原生 TX15 适配设计

日期：2026-09-21。状态：根据已确认方向形成的设计稿；实现细节尚未通过构建或实机验证。

项目名称：New Deviation。项目仓库：https://github.com/ahfynjj/New-Deviation 。

## 目标与不可变边界

为 Deviation 新增 RadioMaster TX15 原生目标，保留 Deviation 的操作体系、复杂混控和模型语义，支持内置 ELRS，适配 480×320 彩屏与触摸，随后逐步增加功能和机型。

- 主工程和应用运行逻辑必须是 Deviation。
- 不把 Deviation 嵌入 EdgeTX 应用框架，不引入 EdgeTX 混控或模型作为主实现。
- EdgeTX 只作为 TX15 硬件定义、启动和外设驱动参考；任何代码复用记录来源、版本、许可及依赖。
- 首版使用内置 ELRS/CRSF；传统直连射频、多协议外置模块和完整 Lua 生态不属于首版验收范围。
- 原 Deviation 目标保持可构建；新的 H7 适配不得用全局替换方式破坏 F1/F2。
- 编译、模拟器、板上启动、射频链路、异常验证分别记录，不互相替代。

## 分层与数据流

```text
TX15 摇杆/开关/触摸/按键
        ↓ Deviation 平台输入接口
Deviation 模型、微调、曲线、复杂混控
        ↓ 通道输出
Deviation CRSF 编解码与模块配置
        ↓ TX15 UART/DMA
内置 ELRS 模块 → 接收机

遥测：ELRS → UART → Deviation CRSF → 遥测状态/页面
界面：Deviation 页面/GUI → 显示接口 → TX15 LCD
存储：Deviation 配置 → 文件系统接口 → 已核实的存储介质
```

首阶段不重写混控算法。保留实际接口，例如 `MIXER_CalcChannels()`、`CLOCK_StartTimer(unsigned us, u16 (*cb)(void))`、`UART_SetDataRate(u32 bps)`、`UART_SetDuplex(uart_duplex duplex)`；实现之前先核对全部调用约定、中断上下文和共享数据。

建议新目标放在 `src/target/tx/radiomaster/tx15/`。H7 专用代码与 F1/F2 分离；是否采用 ST HAL/LL 的局部依赖由驱动审计决定，不能假定现有 libopencm3 分支提供可用 H7 实现。新目录尚未创建，避免空壳目标被误认为可构建固件。

## 彩屏与操作

保留菜单组织、混控参数含义、编辑流程以及实体按键入口。首个原型允许在 480×320 屏幕上显示居中的 320×240 原页面，触摸坐标按实际视口换算；这仅用于打通链路，不作为完成彩屏适配的依据。

后续以原彩屏页面为基础扩展布局，覆盖主界面、模型管理、复杂混控、曲线、通道监视、校准和 CRSF 配置。缩放方式、字体和触摸区域在模拟器中比较后决定，不提前承诺整套视觉重设计。

## 模型兼容

保留配置语义，建立旧模型样本。硬件源编号、开关数量、校准数据和射频选项需要显式映射。遇到未支持的旧协议或不存在的输入，必须提示并禁止不明确的射频输出；不得默默把旧协议改成 ELRS。保存前后的混控行为必须有回归证据。

## 启动和实时约束

先确认现有启动程序、外部 Flash 布局、向量表、SDRAM 初始化及加载/执行地址，再决定兼容启动方式。不能直接沿用旧 DEVO DFU 地址，也不能仅凭 UF2 扩展名推断兼容。

建立时钟、定时器、ADC、UART/DMA、显示 DMA 和缓存一致性清单。控制输出不得依赖 UI 循环持续运行；测量最坏刷新、存储写入、遥测负载下的通道周期和抖动。首版先固定一种双方支持的链路设置，量化门限在 CRSF 专项设计中依据实际协商模式确定。

## 错误处理与实机门槛

- 无效校准、无法加载模型或启动自检失败：显示原因，射频保持禁用。
- 模块通信超时：显示链路状态；分别检查主控停止输出、ELRS 失联与接收机 failsafe，不将三者混为一谈。
- 模型保存中断：验证旧模型或新模型至少有一份可恢复，禁止静默使用部分文件。
- 帧长度/CRC 错误、部分串口帧和异常参数响应：丢弃或限时重试，不阻塞控制循环。
- 首次刷写前保存原固件信息和用户模型，核实下载模式、恢复工具及调试接口；具体设备写入另按当时的实机状态执行。

首个实机里程碑：启动 Deviation → 基础画面 → 输入采样 → 原生混控 → CRSF → 接收机输出。此里程碑只是台架原型，不等于完成飞行验证。
