# New Deviation TX15 MAX USB 更新设计

日期：2026-10-10。状态：待用户审阅的设计，尚未实现、尚未访问或改写实机。

## 用户目标与已确定范围

用户希望自行刷写，避免聊天中反复同步按住/松开电源键。用户已选择“专用更新工具，优先操作简单”。首版操作目标是：关机后按住 EXIT 正常开机，进入更新屏幕，接遥控器数据 USB，电脑选择固件并点击更新；完成后正常关机、再次开机。日常更新不使用调试器，不手填地址、批准令牌或命令。

原生 Deviation 应用、混控、官方 ELRS Lua 及内/外置模块设置沿用；更新默认保留模型和校准。USB 更新模式关闭两个射频模块。触摸、TF卡更新、USB摇杆、运行日志和模型管理不在本首版范围。首次安装新增 USB 启动器需要一次 PWLINK2；启动器严重损坏时仍以 SWD 恢复。

| 方式 | 操作及取舍 | 首版决定 |

首版不声明 STM32CubeProgrammer 兼容，升级数据走原生专用协议。USB设备库拟采用固定版本/提交的 TinyUSB CDC 和 STM32H7 DWC2 支持，保留许可及来源；在实施计划中固定实际依赖并审查内存开销，不使用 EdgeTX 应用、USB任务或烧录框架。

## 已核对代码与硬件依据

- 当前内部启动 BIN 6880B，内部 Flash `0x08000000..0x0801FFFF`，链接器容量128KiB；新增更新器须通过链接/布局校验，不预先保证最终尺寸。
- 外部 NOR 已有实机 JEDEC `0xC84018` 及16MiB几何依据。现有应用从外部偏移0加载；模型/校准区为 `[0xF0000,0x100000)`。
- ND15镜像解析、CRC、段范围、176项向量和入口校验已有 `hardware/tx15/boot/image.c`，完整暂存/加载逻辑已有 `loader.c`。
- 固定板级资料：USB DM=PA11、DP=PA12、AF10、VBUS检测=PH5。EXIT=PG3低有效，原生按键驱动已有使用；USB映射需要实机枚举验证，不能当成已运行证据。
- `early_supply.S`在RAM/栈访问前建立PH12供电保持，更新模式沿用；内部PB13及外部PD4均明确置为模块关闭。
- 现有启动路径使用PLL1=128MHz；显示驱动使用PLL3。USB独立48MHz时钟拟从HSE派生PLL2Q，不能改动PLL1、PLL3及正常应用时钟契约；最终参数和USB供电位按ST手册检查并实测。

USB引脚仅核对已有固定板级资料，应用仍为原生New Deviation。参考固定文件：`D:/DEVI移植/tools/reference/edgetx/radio/src/targets/tx15/hal.h`，固定来源提交见现有 `hardware/tx15/board/power-notes.md`。

## 架构与进入/退出

常驻更新器加入内部启动器，代码/只读数据放内部Flash，USB端点缓冲与状态放已初始化片内RAM；完整镜像放现有独立SDRAM暂存区 `0xD0100000`，不覆盖帧缓冲、目标代码或资源。

冷启动先保持供电并关闭两个模块，在早期稳定采样PG3：EXIT按住进入更新模式，未按住则按现有路径校验并启动应用。按键采样有上拉、消抖及有限等待，不读取TF或依赖应用菜单/I2C扩展器。

若外部应用读不到、格式或完整CRC无效，自动进入USB恢复更新模式；QSPI身份/保护/几何不符时允许显示错误/只读设备信息，但禁止写入。时钟/SDRAM/USB硬件初始化失败时显示可得到的错误，不进入不受约束写入；SWD恢复仍保留。

首版不从运行中的应用直接软复位进入更新器，避免未验证的复位供电及外设切换。应用菜单入口可后续补齐。更新成功后屏幕显示完成，用户用正常电源键关机/再次开机；无需拔电池。电源键在接收/校验/空闲/失败/完成阶段可按释放后长按策略关机，在实际擦写阶段软件忽略关机请求。拔电池或断电仍可能中断当前应用写入。

## 固件文件与兼容性

用户选择单个 `.ndu` 更新文件。它封装现有完整ND15，增加有界固定更新头：格式版本、机型ID、镜像字节数、整包/头CRC、最低更新器协议版本及明确的设置ABI版本；保留字段必须为0。电脑和设备两端都检查范围与版本，拒绝裸ELF、任意BIN、截断包和不同机型。此包装由构建工具从实际产品构建元数据生成，不改ND15内部执行契约。

首版仅接受与当前保存格式兼容的应用；设置ABI版本是源代码和构建契约，改变模型布局时必须升级它，未实现迁移的版本拒绝。旧模型/校准记录兼容行为沿用现有应用。CRC用于检测损坏，不提供签名或来源真实性；不宣称防恶意固件。

## 专用传输与更新事务

Windows工具通过USB CDC通信：只在用户选中与产品描述/USB序列号匹配的更新设备后发送HELLO，不向任意COM口或PWLINK2串口自动发送升级命令。HELLO核对产品、MCU UID、更新器版本、最大镜像长度、设置ABI和只读Flash观察。USB测试标识可配置，开发设备身份必须结合产品字符串、UID及协议验证；不把示例VID/PID作为正式已分配产品标识。

帧使用有界长度、类型、会话ID、序号/偏移和CRC；接收解析须处理USB分段/合并/噪声，限制单帧与总长度。HELLO/读取状态可重试；数据重复帧只有内容、偏移和会话一致时返回既有确认，不追加写入。COMMIT不自动重复提交，超时后先查询同一会话状态；重连/设备重启后不能沿用旧会话授权。

状态：`IDLE → RECEIVING → VALIDATING → READY → ERASING → PROGRAMMING → VERIFYING → DONE`；失败进入带阶段和原因的ERROR。BEGIN/DATA/FINALIZE只操作RAM；完整ND15、更新头、全部CRC/向量及边界通过后才能READY。电脑完成当前64KiB设置区的只读备份并落盘验证后，才开放“更新”；COMMIT还须匹配设备UID、会话、长度、镜像CRC及当前READY状态。

设备在COMMIT前独立再次核对Flash身份、保护状态、几何和镜像，并把原外部首1MiB只读暂存到另一独立SDRAM区 `0xD0200000..0xD02FFFFF`，包含设置及槽尾；它与新镜像暂存区互不重叠。USB请求不能指定任意读写地址：仅允许固件槽和设置备份读接口；内部Flash、选项字节及其它外部区域无写入命令。

写入策略是单应用槽：按4KiB扇区只擦除覆盖新镜像的前缀，所有地址必须 `<0xF0000`，页编程不跨256B边界。先擦除应用头所在扇区，使旧镜像不可误启动；编程镜像正文、最后写入头。所有源数据来自已验证且冻结的RAM缓冲，COMMIT后拒绝对其修改；禁止全片擦除、保护位修改及启动器自更新。

完成后逐字节读回新镜像，重新执行ND15校验，并将64KiB设置区及未触及槽尾与原暂存内容逐字节比较。成功标志必须在这些检查后产生；电脑收到最终DONE、设备屏幕显示完成才能报成功。收到DATA/READY或USB传完不能称为更新成功。

提交前USB中断不会修改Flash。COMMIT后USB中断，在电池仍供电且硬件正常时设备继续已冻结事务；进度查询暂时失败不能判定写入成功。写入期间掉电可能失去旧应用，下一次开机校验失败后进入USB恢复模式，重新完整传包，不承诺断点续传或自动回滚。常驻更新器和模型区不属于应用擦写范围；首版无需占用未知的其它NOR区域建立第二槽。

## 电脑工具

提供Windows小窗口：设备/连接状态、选择固件、更新按钮、当前阶段和进度、成功或明确错误。用户无需配置地址、波特率、令牌或运行命令。备份保存到用户可写的目录，包含UID、时间、设置原始内容及SHA256；不能落盘或校验失败时不提交。首版备份供恢复和诊断，不开放USB写回设置。

开发实现可用Python/Tkinter及串口访问，交付打包为可双击运行的Windows程序；固定依赖和打包路径，不要求用户安装Python。协议核心和GUI分离；可测试核心模拟传输不等于制作遥控器模拟器。设备没有可验证身份时提示用户选择正确设备，不盲扫其它串口。

## 分步验收及一次性启动器安装

1. 先实现并测试纯镜像/协议/事务边界：错误包无擦写、分片/重发/旧会话、跨设置区、超时、写失败与读回失败均拒绝完成；真实模型区数据在事务后逐字节一致。
2. 隔离构建USB枚举/信息读取候选，通过一次RAM实机测试验证USB描述符、Windows驱动、UID和持续传输；此步不写Flash，保留当前固件。
3. 构建带USB常驻入口的内部启动器和受限更新事务、Windows工具，检查128KiB链接限制、RAM/ECC、IRQ与正常应用交接；审查初始化/擦写边界。
4. 现场识别当前已安装版本，重新备份启动器、应用、模型/校准，生成具体一次性启动器更新与回退清单。取得该具体清单刷入批准后使用PWLINK2安装；不能借用ELRS命令版或旧校准版许可。
5. 一次合并实机验收：正常冷启动，EXIT进入USB，工具读取信息/备份并USB更新应用，完成后正常关机开机，确认模型/校准与原有输入/ELRS保留。随后定向验证传输取消和恢复入口；破坏性掉电测试需要明确操作安排，不能先宣称可靠。

完成标准：用户脱离PWLINK2，独立用电脑工具通过TX15数据USB更新一版实际应用，设备完整读回通过并可正常重启，模型和校准保留；错误文件和接收中断均不擦写，应用损坏恢复入口实机通过。软件构建、USB枚举、实际擦写和用户验收分别记录。
