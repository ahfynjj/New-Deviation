# New Deviation TX15：480×320 界面与触摸适配设计

状态：用户已选择“保留 Deviation 结构，重做布局”并批准按本文推进。
P1 独立诊断软件候选已完成，实机触摸尚未验证，尚未启用全局菜单触摸。
本文尺寸、交互阈值和分批顺序为开发建议；实施记录见对应 P1 计划与发布说明。

独立可实施性审查：2026-10-25 已完成，对照当前 I2C、应用入口、GUI 与 Lua
代码核对后无阻塞问题；控制器身份、坐标、原控件错误恢复与 RD02 显示行为
仍按下文阶段门禁验收，不因设计审查通过而视为硬件已通过。

## 目标与边界

保持原生 Deviation 的模型、复杂混控、菜单层级和保存语义，按 TX15 的
480×320 横屏重新布置页面，支持滚轮/实体键与手指共同操作。优先让菜单、
参数编辑、混控和 ELRS 的现有流程可用，再扩展更复杂的手势。

不通过更改屏幕时序“提高分辨率”，不把旧界面整体拉伸，不重写混控引擎，
不导入其他遥控器固件的应用框架，不制作电脑模拟器。当前模型和校准 ABI
保持不变；触摸故障不能影响实体控件、混控、ELRS 或正常关机。

## 路线选择

1. **已选择：保留 Deviation 菜单结构，重做布局。** 核心逻辑和模型不迁移，
   公共控件优先适配，页面分批更新，滚轮操作保持可用。
2. 重新设计导航、页面层级和全部交互：视觉自由度更大，但混控工作流、
   操作习惯和验证范围都扩大，不用于本阶段。

## 480×320 布局建议

- 建立 TX15 专属布局参数，不再用“非 320 分支”代表所有彩屏。
- 默认顶部 36 像素状态/标题区、底部 40 像素操作区，中间 244 像素内容区；
  普通列表采用 40 像素行高，可展示 6 行。复杂混控使用分页/滚动，不能
  为塞满信息把按钮重新缩到难以触摸。Lua 有自己的全屏画布，不强套此布局。
- 正文字体目标 18–20 像素，标题/重要值 22–24 像素；先核对现有字体覆盖
  和资源预算，再决定生成哪些字库。中文支持不是此阶段默认新增范围。
- 交互目标尽量至少 40×40 像素；细箭头可用较大透明命中框，但同一层控件
  命中区不得重叠。控件太密时增加间距或分页，不扩大到相邻参数上。
- 焦点、正在编辑、不可用值三种状态要清楚区分；延续已有橙色编辑提示。
- 点击可编辑参数时完成选择并进入其既有编辑流程；点击左右箭头只调整
  所属字段。滚轮/ENTER/EXIT 与触摸使用相同回调和 OK/Cancel 保存语义。
- 首批支持点击、按住与列表滑动；长按重复只用于明确允许重复的增减控件。
  混控曲线拖动、屏幕键盘和主页自由布局后续单独验收。

建议先用 MAIN MENU 与 Mix 编辑页确定字号、间距和命中尺寸，再迁移其余
页面，避免一次改完后才发现手指操作不合适。

## 触摸软件边界

### 共享 I2C 与控制器

先从 controls.c 提取应用拥有的、带互斥和明确超时的共享 I2C 传输接口，
维持现有扩展输入与音频访问的事务顺序、错误处理和初始化责任。
GT911 等控制器需要独立的 16 位寄存器地址事务，不可复用仅针对扩展器的
8 位 INPUT0 读取函数。触摸驱动只能复位触摸控制器，不复位扩展器、功放
或整条总线。中断只通知“需要采样”，所有 I2C 事务在主循环中完成。

识别阶段使用明确候选地址和有界事务，不做无限扫描或连续复位。先只读
身份/状态，确认协议后才进行必要的复位和数据就绪确认；本阶段不写
控制器永久配置、配置 flash 或系统模型记录。

### 坐标和事件

区分传感器原始坐标、显示物理扫描顺序与最终逻辑 480×320 坐标。
映射统一包含轴交换、翻转、范围变换和裁剪，UI 只使用逻辑坐标。
在四角、中心及边缘验收后才能启用参数点击；不凭 LTDC 的 320×480 扫描
时序直接推断触摸旋转。初期映射随板级配置编译，不增加保存记录 ABI。

建议事件为 DOWN / MOVE / UP / CANCEL，带坐标和时间。一次触摸只捕获
一个控件；滑动成立后抑制点击，抬起不得再次触发 ENTER。优先单指，
额外手指取消本次手势，不任意切换跟踪对象。采样丢失/总线错误导致的
释放使用 CANCEL，不得将故障伪装成一次点击或无限长按。

硬件采样建议间隔 10 ms，事务预算目标不超过 1 ms；手势先用 12 像素
滑动阈值、500 ms 长按阈值，均为可调整默认值，不是已测性能。
共享总线忙时跳过本轮触摸，不能忙等阻塞 RF 服务；主线程分发点击，
runtime 的硬件服务回调只采样/排队，不调用 GUI 或重入 Lua。

### 原生 GUI 与 ELRS Lua

原生 GUI 接入现有命中/释放/焦点逻辑；需复核旧 GUI 是否在按下时即
调用回调。可滚动容器应延迟点击判定到手势分类完成，不能先改值再把
同一次接触解释为滑动。切页、进入弹窗和关机时取消已捕获触摸。

Lua 模式独占其画布范围内触摸，不同时向底层 GUI 派发。兼容 runner 的
新入口保留旧 `nd_lua_run(event)` 调用能力，增加可选触摸状态，再向脚本
传 `run(event, touchState)`，字段按固定脚本实际消费的 swipeLeft/Right/
Up/Down 提供。点击投递 EVT_TOUCH_TAP，滑动只投递一次手势；不要同时
发送触摸事件与等价 NEXT/ENTER 导致重复操作。

当前固定官方脚本的 TAP 表示“操作当前选中项”，并不按点击 Y 坐标选择
任意参数行；必须如实保留这一区别。滑动方向及编辑状态下的行为由原
脚本 touch2evt 决定。若以后要直接点任意参数行，需要另做脚本版本与
兼容性设计，不能声称硬件触摸接通后自然具备该功能。

## 建议实施顺序与验收点

|阶段|工作|退出条件|
|---|---|---|
|P0 基线|记录当前 RD02 的菜单/Lua 显示、速度和 ELRS 行为；保留旧 USB 包|确定可对照版本，不把未确认闪烁混入布局验收|
|P1 基础|布局常量/字体预算清单；共享 I2C 接口；触摸解码、坐标与事件模块；诊断页默认入口|主机回归和 ARM 构建通过；实机身份、四角/中心、按下/移动/释放可核对，暂不改模型|
|P2 首批界面|MAIN MENU、Mix/Src/Switch、模型设置；扩大控件和命中区域|点击箭头与滚轮一致；滑动不误改值；OK/Cancel、来源自动捕获和复杂混控正常|
|P3 Lua|运行器第二参数、专属触摸路由、官方脚本点击与滑动|进入/返回、编辑增减、弹窗和 EXIT 均可用，实体键不退化，无重复事件|
|P4 扩展|主页、Input monitor、校准、音频/存储页、其余参数页|逐页无裁字/越界/命中重叠；校准与模型保留；RF、音频及存储并行正常|

P1 可先把独立触摸诊断作为默认关闭的实验入口，在诊断验收前不全局开启
HAS_TOUCH，不生成一个仅切宏却没有真实轮询入口的“触摸固件”。应用更新
沿用 USB 入口；没有当前证据要求更换启动器或重新焊接调试线。

## 检查与发布边界

主机检查：四角/边缘映射、越界包、多个触点、抖动、丢采样、时钟回绕、
滑动抑制点击、切页取消、I2C 锁/超时/恢复、Lua 第二参数与事件不重复，
以及真实 GUI 命中框与绘制框的一致性。旧滚轮、Src/Switch 捕获、模型与
校准保存、RF 路由和音频回归必须保留。仅使用主机测试，不制作模拟器。

实机检查合并安排：先诊断页确认控制器与坐标，再一次验收首批页面，
随后验收 Lua 及长时间 ELRS 连续性。触摸未接通、包已构建、USB 已写入、
实际操作可用是四个不同状态，发布记录必须分别说明。
