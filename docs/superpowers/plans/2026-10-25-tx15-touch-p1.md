# TX15 touch P1 implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline. Do not
> delegate implementation; request one final independent review.

**Goal:** Deliver a USB application with independent touch identity/coordinate
diagnostics, retaining the native GUI, buttons, RF, audio and settings.

**Architecture:** Publish a bounded shared-I2C API over the existing controls.c
bus owner. Add passive GT911 discovery and incremental frame reads, a pure
coordinate/event processor and an explicitly started diagnostic page. Keep
HAS_TOUCH=0 until real coordinate acceptance. No touch GPIO reset in P1.

**Tech Stack:** Native STM32H750 C, existing Deviation GUI, host C harnesses,
Python unittest, GCC ARM, existing NDU USB updater.

**Spec:** docs/superpowers/specs/2026-10-25-tx15-ui-touch-design.md

## Global constraints

- Baseline a54aa8bb, established dev/tx15-hardware-bringup workspace. Reuse the
  user-directed active checkout and its native build/tool paths.
- Preserve bootloader, settings ABI, display timings and existing input logic.
- No emulator, hardware access, Flash writes or automatic GUI touch enabling.
- Control identity and map are candidates until hardware acceptance.

## Review focus

- Shared-bus lock, STOP/error flags, unchanged expander recovery and audio status.
- At 98kHz, cap public read payload at four bytes and use one transaction per
  driver step; no full 40-byte touch burst or unbounded identity scan.
- Never acknowledge unknown devices or write controller configuration.
- Multiple points/identity changes/errors cancel rather than click or release.
- Diagnostic lifecycle must stop polling and leave normal RF/input services alive.

## Tasks

### 1. Shared I2C transactions

Files: hardware/tx15/board/i2c_bus.h, controls.c;
utils/hardware/tests/test_i2c_bus.py, existing controls/audio tests.

Interface: tx15_i2c_read/write(address, register, register_bytes, data, size).
Returns OK, BUSY, IO, INVALID or UNAVAILABLE; exposes terminal status report.

- [x] Add failing tests for 16-bit big-endian register prefix, little-endian
  payload preservation, bounded reads/writes, busy admission without writes,
  error/timeout status before clear and stopped-clock loop budget.
- [x] Consolidate read_port/audio_transfer on the shared transaction primitive;
  retain input-specific error recovery and existing lock ownership.
- [x] Run new tests plus controls/audio deadline/hardware suites.

Ruling: keep the shared transaction implementation within the existing bus
owner controls.c, with an independent header, instead of moving initialization
and GPIO reset ownership at the same time. This reduces regression scope while
giving touch one supported bus interface. Later file relocation is mechanical.

### 2. Touch protocol and pure input processing

Files: hardware/tx15/board/touch.c/.h, touch_input.c/.h;
utils/hardware/tests/test_touch_input.py and test_touch_driver.py.

Interfaces: start/stop/poll manual diagnostic lifecycle, cached report and event
queue; pure mapping and DOWN/MOVE/UP/CANCEL processing with explicit map flags.

- [x] Write failing tests for candidate addresses 0x5D/0x14, strict product ID,
  config resolution reads, ready/count/track decoding and status-only ACK.
- [x] Implement one <=4-byte transaction per step. Read point data in chunks,
  acknowledge only accepted known-device frames, never write 0x8047 configuration.
- [x] Write/run mapping/event tests: corners, flips/swap, bounds, multiple points,
  ID changes, cancellation, queue overflow and time rollover.
- [x] Add trial-map selection for diagnostics only; no persistent setting.

Ruling: P1 probes passively without driving historical candidate RESET/INT pins.
If the device remains in reset, that is a reported discovery limitation requiring
pin-source verification, not permission to blindly toggle unrelated hardware.

### 3. Application integration and USB candidate

Files: src/target/tx/radiomaster/tx15/runtime.c, app.c, ui_layout.h;
src/pages/320x240x16/touch_test_page.c, pages.h, pagelist.h;
utils/build-tx15-app.py and page/runtime tests.

- [x] Define 480x320 header/content/footer geometry and verify fit; inventory
  font/resource budget without changing global menus yet.
- [x] Add diagnostic page with Probe, Stop, Map, ID/bus/raw/mapped/event fields;
  redraw changed information and marker only, retain ENTER/EXIT navigation.
- [x] Poll via hardware services only while started. Exit stops and cancels.
  Never call GUI from runtime or dispatch touch to background pages.
- [x] Opt-in TX15_TOUCH_DIAGNOSTIC build (UI01); keep older display modes selectable.
- [x] Run host regression, ARM build, final independent review and validate NDU
  ABI/CRC/segments/symbols; preserve prior USB rollback packages.
- [x] Prepare code/evidence and USB instructions for the combined test.
- [ ] Physical identity/coordinate/normal-input acceptance; then advance to P2.

## Baseline / execution ledger

- RD02 is built but its visual/latency/RF hardware acceptance is still pending.
  Diagnostic release must not claim that acceptance or full menu touch support.
- Existing font generation adds 15normal and 23bold; embedded resource use is
  464375/524288 bytes. P1 draws targets and reuses fonts, adds no bitmaps.
- User approved the design and progression; no further design-permission loop.
- Software result: 46 tests passed; 155 ARM objects built and linked, NDU and
  ELF validated. See docs/tx15/touch-p1-2026-10-25.md and its evidence JSON.
- Review found that ready flags could bypass the shared 1ms total deadline.
  Added a reproducing test (each ISR read advances 20000 cycles), observed its
  failure, then checked deadline before accepting flags and before final success.
  Re-ran all 46 checks and rebuilt; focused independent re-review passed.
- No device access or flashing. No touch reset/interrupt pin configuration;
  absence of a passive response is a pending hardware finding, not proof of a
  different controller or a reason to remap pins blindly.
