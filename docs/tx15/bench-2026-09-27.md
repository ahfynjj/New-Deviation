# TX15 MAX 实机记录：2026-09-27

原生 Deviation 路线；允许参考 EdgeTX TX15 的板级适配。本次继续使用 PWLINK2 Lite / CMSIS-DAP、100 kHz SWD 和已有四线连接。

## 当前目标

验证按住按钮复位 → 复位捕获暂停 → 调试器设置 PH12 输出高 → 松开按钮仍可访问且 CPU 保持暂停 → 恢复原固件启动。只操作已核实的易失性调试、GPIO 配置，不写入 Flash、选项字、程序计数器或 RAM 程序。

## 首次连接与 10:08 测试

- 首次只读连接 No ACK；用户随后确认刚开机并重新连接。
- 按钮触发后的复位期间，CPUID 可读，但首次向 `DBGMCU_APB3FZ1 (0x5C001034)` 写看门狗暂停位时返回 FAULT ACK。写入是否生效不能仅凭异常确定。
- 此时尚未执行复位捕获设置或 GPIO 写入，不能声称 CPU 已暂停。
- finally 释放 NRST、恢复原调试寄存器并允许 CPU 运行；读回原应用状态：`DHCSR=0x03010000`、`VTOR=0x20000000`、`RCC_CFGR=0x1B`，PH12 输出高。用户确认屏幕恢复正常。
- 无 Flash/RAM 程序下载。日志：`local/reset-halt-power-20260927-100822.json`。

## 调整后的测试顺序

参考已安装 pyOCD 0.45.1 的 STM32H750 `safe_reset_and_halt()`：复位期间只操作核心 DEMCR/DHCSR，释放复位后才访问外设寄存器。移除导致上次 FAULT 的复位期间看门狗寄存器访问。

捕获成功后，先打开 GPIOH 时钟、通过 BSRR 预置 PH12 高、再设置推挽输出；恢复 PA4 上拉输入以识别松手。设置并读回看门狗调试冻结位，限定等待松手时间，随后自动恢复原固件。所有目标地址写入采用白名单并记录完成状态。

ST 寄存器依据：[STM32H750 CMSIS 头文件](https://github.com/STMicroelectronics/cmsis-device-h7/blob/master/Include/stm32h750xx.h)。`DBGMCU_APB3FZ1` 偏移 0x34 的 bit 6 对应 WWDG1，`APB4FZ1` 偏移 0x54 的 bit 18 对应 IWDG1。

脚本：`local/hardware-session/reset-halt-power.py --arm`，显式 --arm 才访问设备；语法编译通过不代表实机步骤成功。脚本处于本地 bench 区，不是可对未知硬件使用的通用工具。
