# TX15 MAX 六组三位开关与开机提示

用户确认 SA、SB、SC、SD、SE、SF 均为三位开关；本轮先通过 USB 更新应用。PWLINK2 接线已拆除，内部启动器提示延后安装。

应用修正了 SE/SF 的两位定义：六组开关均将低端触点闭合、两触点断开、高端触点闭合分别解码为 0、1、2，保留 20ms 去抖与同时闭合无效规则。Input monitor、源选择、开关选择和混控统一使用三档。

旧 ARM 模型为 3400 字节，新模型为 3404 字节。新版读取旧原始模型及 v1 模型/校准快照，在 RAM 中转换来源编号、反向标志、安全项、微调开关、计时器和页面开关图标。通道条索引、舵机限位、十字盘比例、射频设置及六路校准保留。正常保存使用 v2 快照，避免再次迁移。USB 写入范围仍不包含设置区，更新工具继续自动备份。

旧 SE/SF 的位置 0 是中间，位置 1 合并了两个端点；旧位置 0 转为新版中间档、旧位置 1 转为新版高端档。旧模型若引用 SE/SF，需在更新后核对其三档混控。旧固件不能读取新版保存的 v2 快照，降级时需配合恢复匹配的设置备份，不能只刷回旧应用。

USB 文件：`local/tx15-usb-release/tx15-switches-3pos-20261011.ndu`。通过已验收的专用工具安装，保留当前内部 USB 启动器。此候选采用当前产品源码，也含此前已完成离线检查的 ELRS 命令确认功能；命令实机执行不属于本轮验收。

内部启动器另已实现：完成 SDRAM 初始化后先点亮屏幕，显示 `POWER ON / RELEASE POWER KEY`，再读取外部应用并显示装载进度，最后显示 `STARTING`。供电保持由现有无栈入口建立，没有新增任意长按门槛。更新模式复用已初始化的屏幕，避免再次初始化失败。**这部分仅构建，尚未安装；USB 应用更新无法修改内部启动器。** 开机失败原因尚未实机定位，不能将增加提示等同于已修复失败。

验证以软件检查、ARM 构建、真实旧备份离线迁移为准；新版本三档及冷启动体验仍需更新后实机确认。具体哈希与检查结果见同目录 evidence 记录。

## 三档实机验收未通过，诊断版 r2

用户报告 USB 工具显示更新完成、所选文件名正确，拔掉数据 USB 并断开电池后，Input monitor 和混控仍仅有 SE/SF 两档。原因尚未确认，不能把软件检查通过视为实机修复。

`tx15-switches-3pos-diag-r2-20261011.ndu` 增加可见版本 `3P-r2`：Input monitor 中间显示 SE/SF 当前解码档位与运行时识别的档数、开关扩展器 0x75 原始输入，以及输入屏蔽位。如 `SE:1/3` 表示当前为中间档，系统识别三档；`-` 表示输入无效。屏蔽位及电气触点与混控布尔来源分别显示，避免将每个位置来源的 ±100 真/假值误认为整个开关仅有两档。诊断仅读取已有输入状态，未改解码、模型布局、ELRS 或启动器。相关 13 项检查、132 个 ARM 对象构建及包内版本标记核对通过，实机状态仍待观察。
